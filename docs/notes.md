# 設計取捨、已知限制與未完成項目

## 設計取捨

| 決定 | 理由與代價 |
|---|---|
| JSON 檔＋記憶體快取 | 免安裝資料庫、資料可人工檢視；僅適合單一行程與小資料量。 |
| `IBusinessLock` 取代交易 | 配號、扣庫存、保養產生在鎖內「先檢查再寫入」；寫入中途當機可能只完成部分實體。 |
| 保養工單由背景掃描產生（每 5 分鐘） | 不需排程器；剛到期的計畫最多延遲 5 分鐘，主管可按「檢查並產生工單」。 |
| 前一張保養工單未完工時不產生下一張 | 避免逾期的每日保養堆積大量工單；代價是漏掉的週期不會逐一補開。 |
| 取消保養工單＝略過本期 | 否則「同一週期不可重複產生」會讓計畫停滯。 |
| 驗收退回不回復計畫日期 | 重做完工時依新的完成日重算；待驗收即視為本期完成。 |
| 依使用量的保養以人工登錄使用量觸發 | 沒有設備連線資料來源。完工期限為產生日加「保養工單預設提前產生天數」。 |
| 維修成本＝用料＋外送費用 | 系統沒有工時費率，工時另列不換算金額。 |
| MTBF 以期間內相鄰兩次報修通報的平均間隔估算 | 簡易指標，未扣除停機時間，樣本少時參考性低。 |
| CSP 允許行內樣式 | ECharts、FullCalendar、掃碼元件需要；腳本仍僅限本站檔案。 |

## 已知限制

- 只能單一執行個體部署（記憶體快取與行程內鎖），不可多台共用資料目錄。
- 清單、報表與儀表板在記憶體中計算，資料量大（例如數萬筆工單）時需改資料庫。
- 稽核紀錄與通知不會自動清除；稽核為一般 JSON 檔，能存取伺服器檔案的人可以修改。
- Email 僅寫入 `outbox/` 模擬，沒有重寄機制。
- 外送費用只有累計金額，多次外送時全部歸屬在最後一次回廠日（尚未送回者以外送日計）。
- 資產的累計使用量只能增加；設備更換計數器時需由主管在資產編輯頁修正。
- 掃碼的照片辨識受元件限制，部分照片需靠近重拍；可改用手動輸入。
- 登入頻率限制以來源 IP 計算；放在反向代理後方時需設定轉送標頭，否則所有人共用同一額度。
- 正式部署前需自行處理：更換範例帳號密碼或建立乾淨資料、設定 `AllowedHosts` 與 `App:PublicBaseUrl`、使用正式 HTTPS 憑證、保護並定期備份 `App_Data/`。首次啟動一律由 `SeedData/` 建立資料。
